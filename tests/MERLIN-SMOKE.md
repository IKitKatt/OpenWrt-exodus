# Проверка Exodus в Web Admin Merlin

Поддерживаемые версии: **384.15+** в ветках 3004 (384/386/388), включая
**3004.388.12_2 на RT-AX86U**, и **3006.102.1+** в ветке 3006. Эти проверки требуют настоящего роутера;
изолированные Python/Node-тесты и браузерный preview их не заменяют.
Статус в текущей среде: **не выполнены, доступа к роутеру нет**.

Перед проверкой сохраните `/opt/etc/exodus` и исходные скрипты JFFS. Для миграции
используйте локальную сборку этой ветки: изменения могут ещё не быть опубликованы
в GitHub. Установщик и архив приложения должны относиться к одной ревизии.

Для RT-AX86U с 3004.388.12_2 подтверждён формат NVRAM: `firmver=3.0.0.4`,
`buildno=388.12`, `extendno=2`. Проверить также альтернативный формат
`buildno=388`, `extendno=12_2`: обе записи должны проходить проверку версии.
Для граничных версий `384.14/384.15` и `102.0/102.1` номер доработки берётся
из `buildno`, если он содержит точку, независимо от номера патча в `extendno`.
При отказе установщик должен указать конкретную причину: версия, `am_addons`,
helper или каталог JFFS. Ошибка версии включает прочитанные поля NVRAM.

| Проверка | Действие и ожидаемый результат |
| --- | --- |
| Зависимость Base64 | На роутере без `base64` установщик ставит `coreutils-base64`. `printf Exodus \| base64` выдаёт `RXhvZHVz`, а `printf RXhvZHVz \| base64 -d` — `Exodus`. Если кодирование недоступно, нет `success`, код и конфигурация восстанавливаются при ошибке активации. |
| Меню Merlin | На RT-AX86U 3004.388.12_2 открыть Exodus: видны боковое меню, вкладки VPN и выбранный Exodus. В консоли нет `Mismatched anonymous define() module`; штатный jQuery/Migrate загружается перед `state.js`/RequireJS. Проверить также scMerlin и соседние вкладки. |
| Фоновые запросы | Открыть Exodus, затем загрузить профиль и сохранить настройку: оба вида POST (snapshot и packet) в `/start_apply.htm` содержат `flag=background`. Страница не перезагружается, штатное окно Loading/Complete не появляется, незаписанный текст редактора сохраняется. Первоначальный 404 до готовности ответа допустим; бесконечные 404 требуют проверки `service-event`. |
| Обработчик без setsid | На прошивке без `setsid` проверить получение snapshot и ответа на операцию. Обработчик запускается через `start-stop-daemon` с абсолютным путём `/bin/sh`. |
| Фон страницы | На коротких разделах, при загрузке и при ошибке серый фон Exodus доходит до конца бокового меню и заполняет свободную высоту окна. При изменении меню или размеров окна высота пересчитывается; длинные разделы растут по содержимому. |
| Язык | При `preferred_lang=RU` меню и настройки Exodus на русском; при EN, пустом или другом значении — на английском. Сохранённое `exodus.lang` и язык браузера не влияют. Отдельной кнопки RU/EN нет. |
| Скорость навигации | Первое открытие и переходы между вкладками читают `load/files/hosts/interfaces/proxies/hwid/about` из RAM-кэша и не отправляют apply POST. Проверка обновлений по сети работает в отдельном процессе; ручная проверка остаётся доступной. Изменения через CLI появляются в кэше примерно за 30 секунд, изменения из WebUI — до ответа о завершении. |
| Обновления в фоне | Открыть Updates до завершения первой проверки: сведения и доступность кнопки Update обновляются автоматически после ответа, без apply-запросов. Выбранный режим экономии места сохраняется. При `exodus web stop`, повторной установке или удалении сетевой worker завершается и не публикует поздний ответ. |
| Удаление без id | На прошивке без `id` удалить Exodus, в том числе с повреждённым CLI: нет `id: not found`, собственные процессы остановлены, чужие процессы и аддоны работают. UID определяется через `/proc`; если определить его не удалось, скрипт сообщает ошибку до удаления. |
| Восстановление кэша | Обновить установку, которая создала пустые `.body` из-за отсутствия Base64. Статус и все журналы открываются без `Unexpected end of JSON input`, в том числе журналы, не изменившиеся после обновления. При сбое кодирования новые пустые ответы и heartbeat не публикуются. |
| Совместимость | На 384.15, 386.x, 3004.388.12_2 и 3006.102.1+ с Addons API установка завершается `success`; на 384.14, 3006.102.0, стоковой прошивке и без helper/am_addons прекращается до opkg и замены кода. На 384.x выбор страницы учитывает лимит 10 страниц через helper прошивки. |
| Вход и адрес | Открыть VPN → Exodus по HTTP, HTTPS и нестандартному LAN-порту. `exodus web url` совпадает с рабочим адресом; нет отдельного пароля Exodus. |
| Без сессии | В приватном окне запросить `/userN.asp`, `/ext/exodus/cache/status.json` и известный `/ext/exodus/responses/<id>.json`. Нет конфигурации, секретов или журналов. Login HTML с HTTP 200 считается запретом доступа только при отсутствии этих данных. |
| Истечение сессии | Изменить поле без сохранения, завершить сессию роутера. Запросы приостанавливаются, черновик остаётся. Войти в другой вкладке, возобновить, сохранить изменение. |
| CSRF | С другого origin отправить форму на `start_apply.htm` с `restart_exodus_ui` и собственным `amng_custom`. Прошивка отклоняет запрос: конфигурация и shared settings не меняются. |
| Содержимое | Загрузить и прочитать UTF-8 YAML с кириллицей, emoji, кавычками и буквальным `<% test %>`. Сравнить байты; ASP-шаблоны не исполняются. |
| Размер | Передать допустимый файл 8 MiB; передача длительная, подтверждаются все части. 8 MiB + 1 байт отклоняется до POST. При нехватке RAM — понятная ошибка без частичного применения. |
| Два окна | Одновременно загрузить профиль и сохранить настройки из другой вкладки. Данные разных ID не смешиваются; неполная передача и старые снимки настроек не блокируют другие передачи. Допускается до четырёх незавершённых передач; операции изменения состояния выполняются последовательно. |
| Локальный файл | Загрузить YAML с ПК с кириллицей и emoji, размером больше одной части транспорта. Видны прогресс и занятая кнопка; после завершения файл появляется в списке, содержимое совпадает с исходным. При ошибке нет необработанного JavaScript rejection, можно повторно выбрать тот же файл. Лимит 8 MiB сохраняется. |
| Повтор пакета | Повторить последнюю часть того же ID. Операция применяется один раз; изменившаяся часть отклоняется. |
| Управление | Проверить start/stop/restart прокси и autostart. После proxy stop Web Admin, настройки и журналы доступны. `exodus web stop` снимает только Exodus; `web start` восстанавливает его. |
| Частые чтения | Оставить статус и журналы на несколько минут. Чтения не вызывают native POST/rc_service и не меняют файл shared settings. Остановить кэш: интерфейс показывает недоступный/неизвестный статус. |
| Обновление | Запустить обновление со страницы Exodus. Скрипты заменяются, итоговый ответ того же ID доступен, UI переподключается, секреты и профили сохранены. При ошибке регистрации нет `success`, прежний код и настройки восстановлены. |
| Старый сервер | После миграции нет слушателя старого порта WebUI Exodus. Чужой Lighttpd и его PID/конфигурация продолжают работать. Старые `.web.port` и `web.auth` не изменены. |
| Перезагрузка / USB | Перезагрузить роутер с задержанным появлением Entware. `services-start` не задерживает остальные сервисы, страница появляется после USB, меню содержит один Exodus. |
| Другие аддоны | Проверить уже занятые `userN.asp`, замену видимого меню другим аддоном и обновление чужих settings между частями. Значения с пробелами, пустые строки, кавычки, Unicode и `<%` сохранены. Запрос snapshot не содержит `amng_custom` и не пишет JFFS. Одновременный POST другого аддона отдельно проверить: общий firmware API не предоставляет транзакцию между чтением снимка и POST. |
| Удаление | Выполнить uninstall с `KEEP_CONFIG=1`, затем без него на тестовой установке; повторить с повреждённым CLI. Удалены только страницы, ресурсы, hooks и setting Exodus; при KEEP_CONFIG сохранён `/opt/etc/exodus`. |

Запишите модель, полную версию прошивки, режим/порт Web Admin и результат каждой
строки. Доступ без сессии и чужой origin проверяйте до использования реальных
секретов в интерфейсе.
